Brim's stdio MCP server gives Claude Desktop, Cursor, and other MCP clients three tools:

| Tool           | What it does                                                         |
| -------------- | -------------------------------------------------------------------- |
| `brim_balance` | Reads the vault's USDC balance.                                      |
| `brim_policy`  | Reads this agent's limits, recorded window spend, and freeze status. |
| `brim_fetch`   | Calls a paid API through the scoped agent key and on-chain policy.   |

The tools cannot edit a policy, raise limits, withdraw funds, or replace their configured key. The operator attaches the policy separately; [see vaults and policies](/docs/vaults-and-policies/).

## Connect to the local stack

Complete the [quickstart](/docs/quickstart/) and keep `npm run dev` running. It builds the private workspace packages and creates the local configuration file.

Add this entry to Claude Desktop's MCP configuration or Cursor's `.cursor/mcp.json`. Replace both absolute paths with your checkout location:

```json title="MCP client configuration"
{
  "mcpServers": {
    "brim-local": {
      "command": "node",
      "args": [
        "/absolute/path/to/brim/packages/mcp/dist/cli.js",
        "--local",
        "/absolute/path/to/brim/.brim/local.json"
      ]
    }
  }
}
```

Use Node 24. If your desktop client cannot find `node`, set `command` to its absolute executable path. Refresh the MCP connection, then ask:

> Check my Brim balance and policy. Then use `brim_fetch` to fetch `http://127.0.0.1:4020/report`.

The report costs **$0.04 fake USDC**. Explicit local mode permits only this local report endpoint and uses the generated fake-funds setup.

## Connect your own local agent

[Generate or reuse a scoped keypair and add its public key in the dashboard](/docs/sdk/#register-your-agent-locally). Wait for the policy's on-chain confirmation. Then use that private key file with the same local vault config:

```json title="MCP client configuration"
{
  "mcpServers": {
    "brim-research": {
      "command": "node",
      "args": [
        "/absolute/path/to/brim/packages/mcp/dist/cli.js",
        "--local",
        "/absolute/path/to/brim/.brim/local.json",
        "--agent-key-file",
        "/absolute/path/to/brim/.brim/research-agent.json"
      ]
    }
  }
}
```

The override is accepted **only with `--local`**. It requires an absolute path to a mode-`0600` file containing a valid 64-byte JSON keypair. It changes only the agent key: the vault config, loopback RPC, and local report restriction stay in place. The key is loaded by the MCP process, never supplied to a tool.

Refresh the MCP connection, call `brim_policy` to inspect your new limits, then call `brim_fetch` with `http://127.0.0.1:4020/report`. It costs $0.04 fake USDC. A tool response or receipt alone is not finalized proof, and this call does not insert a ledger row. [The built-in local payment test](/docs/quickstart/#pay-for-the-report) verifies and indexes its own payment separately.

## Tool reference

Call `tools/list` after the MCP initialization handshake to discover these tools. Unknown arguments are rejected; vault config, keys, RPC endpoints, and spending limits cannot be supplied through a tool call.

| Tool           | Arguments                                                                                                                | Decoded JSON result                                                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `brim_balance` | `{}`                                                                                                                     | `balance` as a six-decimal USDC string, `currency: "USDC"`, and `paused`.                                                                                                                                            |
| `brim_policy`  | `{}`                                                                                                                     | `frozen`, `vaultPaused`, `currency`, `maxPerPayment`, `windowBudget`, `recordedWindowSpend`, `windowSeconds`, `windowStartedAt`, `minimumSecondsBetweenPayments`, `strictVendorAllowlist`, and `approvedRecipients`. |
| `brim_fetch`   | Required `url`; optional `method` (`GET` or `POST`) and string `body`. Method defaults to `GET`; a body requires `POST`. | HTTP `status`, a text `body`, and optional `receipt: { network, signature }`.                                                                                                                                        |

Policy amounts are six-decimal USDC strings. Policy times are decimal integer strings; `windowStartedAt` is a Unix timestamp. `approvedRecipients` contains recipient public keys, not domains. `recordedWindowSpend` is stored window usage, not a calculated remaining balance or permission to spend.

With the local stack and `--local` server running, send this request object through your initialized MCP client:

```json title="Local tools/call request"
{
  "jsonrpc": "2.0",
  "id": 7,
  "method": "tools/call",
  "params": {
    "name": "brim_fetch",
    "arguments": {
      "url": "http://127.0.0.1:4020/report"
    }
  }
}
```

On stdio, each JSON-RPC message uses one line. Brim returns **JSON inside a single text block**. Here is an example balance reply.

```json title="Illustrative brim_balance response"
{
  "jsonrpc": "2.0",
  "id": 8,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "{\"balance\":\"12.450000\",\"currency\":\"USDC\",\"paused\":false}"
      }
    ]
  }
}
```

Parse `result.content[0].text` as JSON, or `content[0].text` if your client unwraps the result. A tool failure sets `isError: true` and returns a redacted `{ "code": "...", "message": "..." }` in the text block. Check the decoded `status` for HTTP errors from `brim_fetch`.

## Configure an operator-provided vault config

For a separately prepared environment, run `npm run build:packages` from this repository and configure the same built CLI with your vault config and scoped agent key:

```json title="MCP client configuration"
{
  "mcpServers": {
    "brim": {
      "command": "node",
      "args": ["/absolute/path/to/brim/packages/mcp/dist/cli.js"],
      "env": {
        "BRIM_VAULT_CONFIG": "YOUR_PUBLIC_VAULT_CONFIGURATION",
        "BRIM_AGENT_KEY": "YOUR_SCOPED_KEYPAIR_JSON_ARRAY"
      }
    }
  }
}
```

Brim chooses the public Solana RPC for the vault config's network. To use your own provider, optionally add `SOLANA_RPC_URL`; balance reads and payments use the same connection. An invalid explicit URL fails setup.

The operator must supply a funded vault, an authorized agent policy, and a [compatible facilitator](/docs/x402/). The package is not published to npm; use the built file from your checkout.

For a compatible pay.sh API, pass the provider's URL to `brim_fetch`. [Pay.sh endpoint setup](/docs/x402/#use-paysh-endpoints)

Use the complete `brim:v1:...` string supplied by your operator for `BRIM_VAULT_CONFIG`. `BRIM_AGENT_KEY` comes from the integrator's private runtime configuration as a 64-number JSON keypair string. In this setup, that private runtime is the MCP server process launched by your client. Keep the key out of prompts and tool arguments.

The [SDK handoff guide](/docs/sdk/#who-hands-over-what) explains who generates each value, what it looks like, and why multiple agents can share the public config while retaining separate keys and policies.

## Protection and outcome boundaries

Normal configuration requires HTTPS and refuses credentials embedded in the URL. Local mode permits the loopback report on port `4020`. POST bodies are limited to 16 KiB and sent as `application/json`; response bodies are limited to 64 KiB. Requests time out after 15 seconds, and MCP cancellation interrupts the Effect workflow. The SDK's default $1 per-payment cap and the on-chain policy both apply.

The server retains only the configured scoped agent authority. It offers no owner-write tools, arbitrary request headers, or tool arguments for swapping keys, vaults, RPC providers, or limits. The policy is checked again when the payment executes.

A receipt is merchant-reported metadata, not independent proof of finalized settlement. `PAYMENT_OUTCOME_UNKNOWN`, a paid retry rejection, timeout, or response-size failure requires checking the original payment before authorizing another. Use finalized transaction and program-event verification as demonstrated by the [local payment flow](/docs/quickstart/); the MCP server does not promise invoice idempotency.
