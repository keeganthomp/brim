## The setup

An operator funds a USDC vault and registers the agent's public key with a spending policy. The agent receives two things:

1. **Public vault config**, called a Brim card, with connection details.
2. **A private agent key** that can spend only within the registered policy.

Creating the config does not attach a policy. [See how that attachment works](/docs/vaults-and-policies/).

## What works now

The local stack runs the compiled Solana program, real SDK and MCP payments, and a verified PostgreSQL ledger. The program enforces spending caps, budgets, recipient restrictions, and freeze state.

The dashboard's local workspace reads those actual local balances and payments. Its separate demo workspace simulates funding and policy edits.

Start with the [quickstart](/docs/quickstart/). Live operation still needs owner-wallet integration, authentication, external settlement testing, security review, and deployment.
